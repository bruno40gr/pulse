# Odeon navigation

## Current UX prototype scope

The local Contacts host disables the Filters button and does not mount an open filter drawer; filter implementation is not part of this prototype review. Its toolbar position remains reserved. Families/Students, Table Preferences and profile-name actions remain interactive. Family groups use separate holder/detail rows, one checkbox aligned to the holder, alternating group backgrounds, whole-group hover/focus and a distinct selected highlight. These table interaction styles are opt-in; unrelated tables retain their defaults. Browser coverage checks actual checkbox/name center alignment and computed zebra/hover/selection colors at 1440px and 390px. Earlier filter-drawer notes below describe the retained implementation, not the enabled local prototype scope.

No Preview Home or temporary top navigation strip. Local review starts at http://127.0.0.1:3197/dashboard/contacts. The existing dashboard sidebar includes Enrollments, opening /dashboard/enrollments with the enrollment table and per-record ProgressStepper. Clicking a progress/name resumes the saved draft. Contacts header offers + Enroll contact beside sync and Import Contacts; it opens /dashboard/enrollments?start=1 and the new-draft editor. The one-shot parameter is removed after opening so a reload does not repeatedly create a new draft. No automatic person selection is implied by the global Contacts header action.

Local lab Contacts renders the actual repository Contacts page through the V3 workspace's optional contacts renderer: the real table and controls remain visible, not the prototype ContactsTable. Clicking a mapped student's or account manager's name opens the existing V3 family slidepanel, including Billing and Edit Contact. The lab-only adapter maps fictional contact IDs to the workspace account/student scope; unmatched names retain the legacy panel behavior. The repository Contacts page exposes an optional name-open callback, with live behavior unchanged when it is absent. Lab-only read adapters supply fictional contacts and empty tenant-field/sync metadata; no production API or data connection is mounted. The real page retains search, filters, import, Add contact, selection and contextual message controls. Those controls are not a claim that the lab implements production writes. No live contact-source replacement or migration is performed. Parent portal remains available by explicit direct preview URL /students?prototype=v3&view=parent&account=preview:kim, not a Contacts header action. School Setup stays separate at /school-setup. /odeon redirects to Contacts for old bookmarks.

Enrollment drafts are browser-local and do not yet create a student/subscription in the staff workspace. Family/billing changes are in-memory fictional data. No live booking or real payments.

The enrollment mock-data banner and draft-only header subtitle are omitted from the UI at the owner's request. Actual save/load errors remain visible. Removing the notices does not change persistence, booking or simulated-payment behavior.

The integrated lab toolbar follows Search → Filters → View students / View families → Table Preferences. Filters opens a right-side drawer (full screen on mobile), with Name, Status, Email, Last active, Instructor, Program, Service / class and Funding fields. Submit search applies draft values and closes the drawer; closing without submitting discards unapplied changes on reopening. Clear filters resets draft and applied values. Applied filters are counted on the Filters button. The footer stays visible while the field area scrolls. Students is the default; Families shows each account holder once with their students underneath, including when a child matches an applied filter. Filters remain applied across views, while row selection resets when changing views. Table Preferences toggles column visibility for the current mount; Name is always visible. The lab supplies fictional enrollment-derived filter options. Status matching is case-insensitive, and multi-valued program/instructor/service fields match individual values.
